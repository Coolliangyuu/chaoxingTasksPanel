# 学习通作业看板 v1.5.0

Windows x64 作业看板，查询作业、提交状态、截止倒计时和账号登录状态。使用学习通官方登录页面，保留此前的账号管理、作业详情、附件下载和更新检查功能。

## 系统与体积要求

- 本体框架为 .NET 10 Windows Forms，浏览器控件为 Microsoft Edge WebView2（SDK 1.0.3595.46）。.NET 运行时随单文件发布，仍需要系统安装 WebView2 Runtime。
- **本软件此次发布的统一门槛**为 Windows 10 22H2（内部版本 19045）或更新的 64 位 Windows，包含 Windows 11。Windows 10 1507、21H2 等低于此门槛的系统不能安装或启动。这里的门槛是本软件的发布兼容策略，不代表 .NET 10 的绝对技术下限。
- 微软的 .NET 10 支持表还列有部分更旧的 Windows 10 LTSC/企业版，系统的生命周期支持和本软件的运行门槛需要分开理解。参考：[.NET Windows 支持表](https://learn.microsoft.com/en-us/dotnet/core/install/windows)、[WebView2 支持范围](https://learn.microsoft.com/en-us/microsoft-edge/webview2/)。
- MSI 在图形和静默安装路径都执行原生系统检查；便携版在 .NET 加载前执行原生预检，不满足要求时提示并退出。托管入口另有同一策略的检查。系统版本读取采用真实版本查询，不依赖容易受兼容模式影响的显示名称。
- 为兼容早期补丁的 Windows 10 22H2，此构建使用微软文档中的 `<CetCompat>false</CetCompat>` 应用发布选项，避免 CoreCLR 在进入 Main 前因旧系统的 CET 问题直接退出。本应用因此不启用 CET 硬件影子栈保护；CFG、DEP、ASLR、原生版本拦截和 x64 异常展开信息仍保留，不修改系统的全局安全设置。参考[微软 CET 兼容说明](https://learn.microsoft.com/en-us/dotnet/core/compatibility/interop/9.0/cet-support)和[.NET 启动问题记录](https://github.com/dotnet/runtime/issues/121596)。
- 启动前显式检测 WebView2 Runtime。缺少时显示中文提示，可由用户选择打开微软官方安装页；原生加载器错误与缺少运行时会分别提示。启动异常写入 `%LOCALAPPDATA%/ChaoxingStudyTasks/startup.log`，日志超过 128 KB 后轮换一次；异常时显示错误，避免无提示退出。
- EXE、MSI 各自均限制在 100 MB 以内（十进制）。圆角按钮使用现有 WinForms/GDI+ 绘制，不增加第三方 UI 框架。原生预检直接添加到现有单文件入口，保留 CFG 和 x64 异常展开信息，不套外层解压启动器，不增加一份程序缓存。文件体积限制不等于浏览器运行内存或浏览器数据缓存限制。
- 按钮采用接近安装包的青色、浅色描边和轻微圆角，保留原控件的大小、间距、键盘操作和板块相对布局。独立作业详情及附件预览窗口由 1140×820 调整为 1240×820，即只加宽 100 px。

## 使用

- 便携版本体为 `chaoxingTaskPanel.exe`，双击运行。启动和发送截止提醒都不会创建桌面或开始菜单快捷方式，也不创建开始菜单文件夹。
- MSI 安装版采用完整向导：欢迎 → 安装位置 → 准备安装 → 安装进度 → 完成。默认位置为 `Program Files/chaoxingTasksPanel`，可直接输入路径或点击「浏览」选择文件夹。安装后创建桌面及开始菜单快捷方式，可在 Windows「设置 → 应用 → 已安装的应用」中卸载。卸载由 Windows Installer 提供，无需单独的 Uninstall.exe。
- 安装位置保存在 64 位 `HKLM/Software/CoolLiangYu/chaoxingTasksPanel/InstallDir`。后续升级安装包在计算安装路径前读取该记录，默认沿用原位置；显式指定的 `INSTALLDIR` 优先。升级前读取位置，再移除旧版本，最后由新版本写回记录。向导也提供修复、卸载和取消结果页面。
- 已安装的用户可直接运行本修订及之后新构建的 MSI 升级，无需先手动卸载。向导会显示升级流程，沿用原安装位置，替换程序文件并保留账号、浏览器会话、提醒设置和开机自启动。升级前请从托盘选择「退出面板」并确认；仅关闭主窗口仍会占用程序文件。
- 每个新构建的 MSI 有独立 ProductCode 和 PackageCode，UpgradeCode 保持不变，升级范围包含同为 1.5.0 的旧修订。同一份 MSI 再次运行时仍提供修复/卸载。安装版本从 EXE 文件版本的前三段读取，内部递增修订号另外保存于安装包元数据，不改变界面显示的 1.5.0；新机制可以拒绝旧修订覆盖更新修订。此前发布的旧安装包无法补上此校验，请使用此修订或之后的包升级。
- MSI 安装向导使用简体中文，包含安装、卸载、完成和错误提示；已设置中文语言、编码和字体。Windows 的系统权限窗口由系统决定其显示语言。
- 点击「开始安装／升级／修复／卸载」后，将当前向导窗口交给 Windows Installer 作为窗口所有者，并显式保留正常 UAC 提权提示，同时请求前台激活。UAC 是否需要显示、是否使用安全桌面及其最终前台行为仍由 Windows 和系统策略决定，不关闭或绕过 UAC。参考 [MsiSetInternalUI](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msisetinternalui)。
- 从 Windows 设置或同一安装包卸载时，询问是否同时删除用户数据。默认「否」保留数据；「是」在卸载事务成功提交后清理；「取消」停止卸载。升级替换旧版本时跳过询问与清理。新流程需要先安装／升级到本修订，旧版已经缓存的安装包不会自动获得此功能。
- 清理范围是**当前执行卸载的 Windows 用户**：`%LOCALAPPDATA%/ChaoxingStudyTasks` 下全部软件账号、浏览器会话、设置、提醒记录和日志，凭据管理器中本应用专属的登录凭据、本应用通知历史及通知设置，以及默认单文件运行缓存和经应用标识核实的旧用户快捷方式。卸载成功后无论是否删除数据，均移除本应用的开机启动项。其他 Windows 用户、共享 WebView2 运行时和另存到外部位置的作业附件不会删除。便携版与安装版共用上述账号数据，因此选择删除也会清理这份共享数据。
- 清理动作在原用户身份下运行，核实 SID 与系统已知数据路径；限制固定目录名，目录联接／符号链接只解除链接，不递归进入其目标；被占用或无权删除的项目会报告清理不完整。默认运行缓存仅包括 `%LOCALAPPDATA%/Temp/.net/chaoxingTaskPanel` 和 `chaoxingTaskPanel-portable`，自行改名的便携 EXE 或自定义 .NET 解压路径需要自行清理。无交互的 `/qn` 卸载默认保留数据；明确传入 `DELETEUSERDATA=1` 才清理。
- 默认向导使用内嵌的原生现代界面：深色步骤侧栏、白色内容区、卡片式路径输入与青色主按钮。「浏览文件夹」调用 Windows 现代文件夹选择器，支持直接修改路径、Ctrl+A 全选以及中文/空格路径。界面随 DPI 缩放。企业策略禁用内嵌界面时保留原生 MSI 备用向导，已修复 2810 导航链错误。
- 两种版本使用同一份 EXE。GitHub 发布时可以把便携版附件重命名为 `chaoxingTaskPanel-portable.exe`。
- 仅 MSI 安装过程创建快捷方式，桌面及开始菜单快捷方式名称均为「学习通作业看板」，开始菜单文件夹也使用此中文名；程序运行时不创建、修复或改写快捷方式。旧版便携程序曾在第一次提醒时生成的快捷方式可手动删除，本修订不会重新创建。
- 首次运行或从旧版升级时询问是否开机启动，之后可在「设置」中修改。自动启动时收起到通知区域。
- 运行期间始终保留托盘图标。点击主窗口「×」或最小化只隐藏窗口，后台同步与作业截止提醒继续运行。双击托盘图标或右键选择「打开主窗口」可恢复原窗口。
- 托盘右键菜单只有「打开主窗口」「退出面板」。选择「退出面板」后询问「确认要退出？」，并提示退出将停止后台同步和截止提醒；点击「是」才真正退出，点击「否」或关闭确认框则继续运行。
- 首次启动先弹出开机启动询问，关闭后再检查更新。默认开启「启动时自动检查更新」；可在设置中关闭，手动检查不受影响。
- 自动检查使用设置中所选的更新源；GitHub 请求失败时自动尝试 Gitee。发现新版本后询问是否前往下载，并打开实际查询成功来源的发行页。临时回退不改变你保存的首选更新源。
- 无新版本或自动检查失败时不打扰。手动检查显示失败信息；不会自动下载或安装文件。
- Windows 通知在应用运行、已有成功同步的作业数据时有效。关闭主窗口后仍会提醒，从托盘确认退出面板后才停止提醒；请允许该应用的系统通知。程序每 5 分钟同步作业，每 15 秒检查提醒时间，因此可能有少量延迟。
- 安装版在确认当前 EXE 与 MSI 保存的位置一致、且已有中文开始菜单快捷方式时沿用 Windows Toast。便携版或快捷方式缺失时使用现有托盘图标提醒；多个提醒排队显示。此路径不创建快捷方式，也不需要安装其他通知框架。点击托盘提醒可恢复主窗口。
- 传统桌面 Toast 的 AppUserModelID 方式要求已有有效的开始菜单快捷方式，参考[微软说明](https://learn.microsoft.com/en-us/windows/win32/shell/enable-desktop-toast-with-appusermodelid)。便携版使用[托盘通知](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon.showballoontip?view=windowsdesktop-10.0)避免这一依赖。
- 默认提前 48、24、12、6、3、1.5、1 小时，以及 30、15、10、5、3、2、1 分钟提醒，截止后提醒一次。「设置 → 修改提醒时间」可用 ＋ 添加小时/分钟、用 − 删除，确定保存，取消放弃修改。
- 「设置 → 测试通知」点击后立即发送一条独立测试通知，不需要等作业截止；可重复测试，不改变真实作业的提醒记录或提醒开关。发送失败时显示原因。安装版测试还查询 Windows 通知中心确认是否收到；若已收到但没有横幅，请检查 Windows 通知横幅与勿扰模式。
- 通知诊断记录位于 `%LOCALAPPDATA%/ChaoxingStudyTasks/notifications.log`，记录通道、发送结果和失败原因，不记录作业正文；日志超过 128 KB 后轮换一次。修复了新通知身份首次查询状态返回“找不到元素”时提前中止发送的问题。
- 休眠后错过多个提醒时间时合并为一次当前提醒；历史过期作业不集中补发。提醒记录保留，避免重启后重复发送；失败会重试。
- 浏览器页面可能要求重新登录或验证，请在应用内完成，查看登录状态后再刷新。
- 数据位于 `%LOCALAPPDATA%/ChaoxingStudyTasks`，与旧版共用。卸载默认保留，可选择删除；便携版移动后如启用了自启动，应运行一次以更新路径。
- 运行需要 Windows x64 和 Microsoft Edge WebView2 Runtime；EXE 已包含 .NET 运行时。

## 构建

Windows 上安装 .NET 10 SDK、Python 3，以及提供 `g++.exe`、`windres.exe` 的 MinGW-w64 工具链（加入 PATH），在本目录运行 PowerShell：

```powershell
./build.ps1
```

输出在 `dist`，MSI 使用 Windows 自带 makecab 与 Windows Installer COM 接口生成。`InstallerUI/ModernUI.cpp` 编译为内嵌 UI DLL，使用系统 Win32/Shell/MSI API，C++ 运行库静态链接；无需另装 .NET 来显示安装向导，也不需要外置安装 EXE。临时构建文件位于 `work`。`version-history.txt` 会内置到应用 EXE。

运行回归检查（请给每次运行使用一个新的结果目录，避免复用提醒记录）：

```powershell
New-Item -ItemType Directory -Force work/check-01
dotnet run --project verification/FeatureChecks.csproj -c Release -- "$PWD/work/check-01"
```

检查使用虚构作业和模拟通知发送，不发送真实 Windows 通知，不修改自启动项。会生成测试记录和设置窗口截图。

`verification/Check-Upgrade.ps1` 使用随机测试产品/升级/组件 GUID、私有 HKCU 键及工作目录文件，执行真实 MSI 安装→同号升级→重复运行→降级拦截→跨版本升级→卸载清理，未升级或卸载真实应用。已复现重复 ProductCode 与不同产品版本产生 1638，并验证新包可直接升级旧 1.5.0 修订、原中文安装位置及非安装包管理的个人文件保留。

旧产品移除安排在 InstallInitialize 之后、文件操作之前，由 MSI 事务负责回滚。当前非管理员令牌下的独立失败回滚测试，恢复 Windows Installer 受保护注册信息时出现权限错误，已清理临时测试产品；因此未将完整回滚标为验证通过。使用管理员终端运行该脚本并加 `-WithRollback` 可检查故意失败后的注册及文件恢复。

## 重复测试首次启动询问

1. 从软件托盘菜单点「退出面板」，再选「是」，确认程序已完全关闭。关闭主窗口或最小化不会退出，重复启动只会唤回现有窗口。
2. 按 Win+R 输入 `%LOCALAPPDATA%\ChaoxingStudyTasks`，用记事本打开 `settings.json`。
3. 把 `"StartupPromptHandled": true` 改成 `"StartupPromptHandled": false`，保存。其他字段保持原样。
4. 重新运行程序，会先重新询问是否开机启动；回答后再执行自动检查更新。

此方法保留账号、登录状态、提醒时间和更新设置。再次测试时重复上述步骤即可。文件不存在时，本来就会按首次启动处理。

自动更新提示只在来源的正式版号高于 1.5.0 时出现；没有新版本时只会看到开机启动询问。两种版本均保持 1.5.0，本修订不会把同为 1.5.0 的发行版识别为新版本。

已经安装旧的 1.5.0 MSI 时，从托盘退出程序后直接运行本修订安装包即可升级，无需先卸载；便携版退出后替换 EXE 即可。

## 恢复到未打开过的默认状态

1. 若曾启用开机自启动，先在设置中关闭；若配置过永久登录，先在账号管理中关闭该账号的永久登录，清除保存的 Windows 凭据。
2. 从托盘选择「退出面板」→「是」，确认程序完全退出。
3. 在资源管理器中打开 `%LOCALAPPDATA%`，删除 `ChaoxingStudyTasks` 整个文件夹；也可先将它重命名为 `ChaoxingStudyTasks.backup` 以便恢复。
4. 重新运行软件，会重新生成默认账号资料、默认设置并询问是否开机启动。

这会清除账号会话、浏览器缓存、设置、更新源、提醒记录和诊断日志。安装版和便携版共用此数据目录。只需重新测试首次询问时，可按上一节只修改 `StartupPromptHandled`，或者退出后仅删除 `settings.json`（同时会重置提醒、自启动询问和自动检查更新的应用设置）。不用删除 EXE 或 MSI；仅重装软件不会自动清除此目录。
